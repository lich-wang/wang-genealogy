## 导入建议

数据层面可以进入 D1，但建议不要一次执行 1,000 人的细粒度 API 写入：

1. 以 100–200 人为一个事务批次，单次最多 250 人；同一时间只运行一个导入进程。
2. 每个批次先使用最新只读快照运行 `import-kinship.mjs --dry-run`。
3. API 应先按 CBDB ID 做集合式去重，再批量写入最小差量；重跑必须是零写入 no-op。
4. 每完成一个原始分片，核对 created / reused / skipped-no-op 计数，再继续下一片。
5. D1 额度或请求错误出现时停止，保留游标；不要从头重跑已确认完成的批次。

当前 `import-kinship.mjs` 已对 8 个原始分片逐一完成本地快照 dry-run，全部解析通过且未写数据库。若生产导入器还没有 100–200 人子批次参数，应先机械拆分执行文件，或使用集合式批量 API，而不是并发运行多个 1,000 人计划。
