# 产品范围

## 一、目标

建立一个围绕王姓历史人物、宗族支派和亲属关系的公开知识库，使每条人物信息和谱系关系都能回答：

- 谁提出了这条资料？
- 依据什么来源？
- 来源定位在哪里？
- 当前是已采纳、待核实、争议还是撤回？
- 过去被怎样修改过？

## 二、首期范围

首期只处理：

- 已故历史人物；
- 人物姓名、异名、字、号、谱名、排行；
- 生卒时间及其不确定表达；
- 谱籍地、祖籍、迁居地和所属支派；
- 父母、子女、配偶、收养、出嗣等谱系关系（仅以配偶身份出现的人物只记录关系与姓名，不展开其基本信息）；
- 堂号、郡望、始祖、始迁祖、字辈等宗族信息；
- 公开资料接口、公开书目、人工考证和用户投稿；
- 文本引用、卷页、URL、外部数据 ID 等来源定位。

首期明确不处理：

- 在世人物；
- 身份证、联系方式、精确住址等个人信息；
- 族谱扫描影像、照片、音视频；
- DNA、医疗、宗教和其他敏感信息；
- 付费查谱、宗亲社交、电商或宗祠募捐。

## 三、用户角色

### 访客

- 匿名阅读已公开人物、主张、来源和历史版本；
- 从首页直接进入家族树（得姓先祖姬晋、宗敬、毕公高、田安、比干优先，其余位置列出亲属关系最完整的人物），或从任一人物页、搜索结果打开其家族树；
- 搜索人物、支派、地点和来源（简繁字形任填其一即可）；
- 重名搜索结果同时展示生卒、籍贯、支派、字／号／别名和已记录亲属数，并允许先打开人物页核对；
- 在简体与繁體之间切换阅读字形；
- 查看争议资料，但不能修改。

### 贡献者

- 创建候选人物；
- 为人物提交基础信息、父母、子女等主张；
- 为已有主张补充来源；
- 建议修改、撤回或标记争议；
- 提出重复人物合并建议。

### 人物维护者

- 关注并维护指定人物；
- 审阅其他用户对该人物的修改；
- 在同时维护两个重复人物且不存在高风险冲突时发起软合并。

维护权不是历史人物的“所有权”，不能阻止其他用户提交有来源的不同资料。

### 审核者/管理员

- 审核高风险修改和争议；
- 执行或撤销人物合并；
- 处理垃圾内容、侵权、隐私和许可问题；
- 冻结被频繁破坏的条目。

## 四、核心页面

1. 人物页：以「字段—取值」的形式先给出基本信息（姓名、生卒、籍贯、生平）与亲属关系；每条取值旁的「来源 N」默认折叠，悬停可见来源标题，点开是完整引用、版本与可信度。**并存的不同说法不折叠**，就并列在推荐值旁边——折叠的是出处，不是分歧。
2. 家族树页（`/persons/{id}/tree`）：**图形化**世系图——按世代分行，祖先在上、本人居中（配偶以 ⚭ 虚线相连）、后代始终向下，跨代关系保留来源确认的真实代距。默认先显示上下各两代；「展开全部」加载该人物所在的完整公开家族图并一键适配画布。点人物后自动收起叔伯、兄弟姐妹、堂亲等旁系，只保留此人的全部父辈与子辈主干及主干配偶；返回全局视图时不必重新加载。**每条连线上标注依据**（如来源简称与定位），点击在下方列出该关系的全部引用，不向普通读者暴露内部主张 ID；有争议的关系用警示色虚线画出。
3. 主张页：主张内容、支持来源、反对意见、版本和维护者讨论。
4. 来源页：书目/API/网页信息，以及被哪些主张引用。
5. 支派页：谱籍地、堂号、始迁祖、字辈和成员范围。
6. 合并页：两个候选人物的并列差异、证据、影响范围和审核结果。
7. 最近修改：公开展示新增、修改、回滚、争议和合并记录。

贡献表单按人物姓名搜索和选择，不要求复制内部 ID。新增亲属关系时先展示第一位人物已有的亲属，再以关系卡片选择方向、选择第二位人物，并用自然语言预览「谁是谁的什么人」；两位人物同名时必须提示再次核对身份线索。先祖/后代若能由来源确认相隔代数，填写具体整数并在人物页和家族树中展示；无法确认时明确显示「代数不详」，不自行推算。

全站提供简体／繁體两种阅读字形（页头切换，选择记在本地）：

- 界面文字按所选字形显示；
- 人物摘要、搜索结果、关系链接按所选字形显示，原文可通过悬浮提示查看；
- 主张卡片和来源摘录以录入原文为主，另附标注过的自动转换结果——来源原文不会被改写；
- 拼音等罗马字标记不做转换；
- 录入时按来源原文填写，不要为统一字形而改写姓名。

## 五、成功标准

MVP 应能做到：

- 每个人物有稳定 URL 与 API；
- 任意公开字段都能追溯到至少一个主张；
- 任意关系主张可以挂接多个来源；
- 修改不会破坏旧版本；
- 重复人物合并后旧链接仍有效；
- 能导出某个人物及其关系、主张和来源；
- 未满足“已故历史人物”条件的数据不会公开；
- 同一人物不因简繁字形差异被录入或检索成两个人。
