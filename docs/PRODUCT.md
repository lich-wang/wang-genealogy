# 产品范围

## 一、目标

建立一个围绕王姓历史人物、宗族支派和亲属关系的公开知识库，使每条人物信息和谱系关系都能回答：

- 谁提出了这条资料？
- 依据什么来源？
- 来源定位在哪里？
- 当前是已采纳、待核实、争议还是撤回？
- 过去被怎样修改过？

## 二、首期范围

首期只处理：

- 已故历史人物；
- 人物姓名、异名、字、号、谱名、排行；
- 生卒时间及其不确定表达；
- 谱籍地、祖籍、迁居地和所属支派；
- 父母、子女、配偶、收养、出嗣等谱系关系；
- 堂号、郡望、始祖、始迁祖、字辈等宗族信息；
- 公开资料接口、公开书目、人工考证和用户投稿；
- 文本引用、卷页、URL、外部数据 ID 等来源定位。

首期明确不处理：

- 在世人物；
- 身份证、联系方式、精确住址等个人信息；
- 族谱扫描影像、照片、音视频；
- DNA、医疗、宗教和其他敏感信息；
- 付费查谱、宗亲社交、电商或宗祠募捐。

## 三、用户角色

### 访客

- 匿名阅读已公开人物、主张、来源和历史版本；
- 搜索人物、支派、地点和来源；
- 查看争议资料，但不能修改。

### 贡献者

- 创建候选人物；
- 为人物提交基础信息、父母、子女等主张；
- 为已有主张补充来源；
- 建议修改、撤回或标记争议；
- 提出重复人物合并建议。

### 人物维护者

- 关注并维护指定人物；
- 审阅其他用户对该人物的修改；
- 在同时维护两个重复人物且不存在高风险冲突时发起软合并。

维护权不是历史人物的“所有权”，不能阻止其他用户提交有来源的不同资料。

### 审核者/管理员

- 审核高风险修改和争议；
- 执行或撤销人物合并；
- 处理垃圾内容、侵权、隐私和许可问题；
- 冻结被频繁破坏的条目。

## 四、核心页面

1. 人物页：当前摘要、全部主张、亲属关系、支派、来源和历史。
2. 主张页：主张内容、支持来源、反对意见、版本和维护者讨论。
3. 来源页：书目/API/网页信息，以及被哪些主张引用。
4. 支派页：谱籍地、堂号、始迁祖、字辈和成员范围。
5. 合并页：两个候选人物的并列差异、证据、影响范围和审核结果。
6. 最近修改：公开展示新增、修改、回滚、争议和合并记录。

## 五、成功标准

MVP 应能做到：

- 每个人物有稳定 URL 与 API；
- 任意公开字段都能追溯到至少一个主张；
- 任意关系主张可以挂接多个来源；
- 修改不会破坏旧版本；
- 重复人物合并后旧链接仍有效；
- 能导出某个人物及其关系、主张和来源；
- 未满足“已故历史人物”条件的数据不会公开。
